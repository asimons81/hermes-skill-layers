# Demo procedure

Use an isolated Hermes profile and only the original synthetic release-notes fixture. Record the actual Hermes Desktop and native skill tools. Do not use mock browser screens or private installed skills. Start with the reviewed plugin commit and record its full SHA and payload hash outside the source tree.

## Rehearsal: about 75 seconds

| Time | Actual action | Point to show |
| --- | --- | --- |
| 0–10s | Select the synthetic source and prepare a derivative review | Source is retained; candidate is not yet an installed skill |
| 10–20s | Publish the reviewed candidate and show its native selector | A new ordinary skill with a unique name |
| 20–30s | View and patch that selector through Hermes' native skill tools; capture a checkpoint | Native writable copy and a preserved recovery point |
| 30–45s | Intentionally update a different line in the synthetic source; prepare refresh and publish | Both independent improvements survive |
| 45–60s | Make overlapping synthetic edits, prepare refresh, show blocked publication and captured sides, explicitly resolve | Conflict decisions belong to the operator |
| 60–75s | Prepare and publish rollback; show distinct older exports still present | New identity, preserved history, explicit version selection |

Show “a clean textual merge does not establish correct behavior” and the point-in-time capture limitation in the recording or its accompanying text. Keep hashes out of the main narration unless needed to explain a check; make the actual review and selector legible. Inspect the complete rendered recording and use a media probe to verify its real duration is under 90 seconds. A script or planned timing is not recording evidence.

## Submission checklist

- Product and compatibility gates have evidence on the exact source commit.
- Public repository and one-file Hermes catalog PR pin that commit and version.
- Actual recording exists, was inspected, and has a measured duration below 90 seconds.
- The X caption names what the demo proves and tags `@NousResearch`; it does not claim autonomous learning or behavioral validation.
- Recheck the official announcement, deadline, and entry-form fields. Do not invent contact details or a receipt.
- Obtain approval for the concrete caption/video before posting. Record the public X URL only after publication.
- Submit the entry form only with the required real links and the user's authorization; verify its confirmation.

A prepared packet, an open catalog PR, and a fully submitted hackathon entry are separate states. The release handoff records which state is supported by evidence.
